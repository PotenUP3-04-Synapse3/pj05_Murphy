# SLA 교수법 적용 정리

## CLT 기반 PBL로 설계된 영어 문제 해결 시뮬레이션

## 1. 핵심 주장

> 이 프로젝트에 적용된 SLA 교수법은 **CLT 기반의 PBL**이라고 볼 수 있습니다.
> 
> 
> 사용자는 문법 지식을 먼저 배우고 적용하는 것이 아니라, 실제 해외여행 돌발 상황에서 영어를 사용해 문제를 해결하는 과정에서 회화 능력을 습득합니다.
> 

본 프로젝트는 단순한 영어 회화 게임이 아니라,

사용자가 입국심사, 수하물 분실, 공항 직원 응대 같은 상황에서

**영어로 의사소통하고 문제를 해결하는 실전형 학습 시뮬레이션**입니다.

---

## 2. 기존 영어 교수법의 한계

CLT는 기존의 구문 반복, 문법 중심 교수법에 대한 문제의식에서 등장했습니다.

특히 **ALM(Audio-Lingual Method)** 이후의 영어 교수법은

정해진 문형을 반복하고, 정확한 문법 구조를 익히는 데 초점을 두었습니다.

하지만 이러한 방식은 다음과 같은 한계를 가집니다.

| 기존 교수법의 특징 | 한계 |
| --- | --- |
| 구문 반복 drill 중심 | 정해진 문장은 말할 수 있지만 실제 상황에서는 응용하기 어려움 |
| 문법 정확성 중심 | 의미 전달보다 오류 수정에 과도하게 집중함 |
| 교사 주도 수업 | 학습자가 직접 의미를 구성하고 말할 기회가 부족함 |
| 실제 맥락 부족 | 교실에서 배운 표현이 실제 대화 상황으로 잘 전이되지 않음 |
| 정답 중심 학습 | 예상 밖 질문이나 돌발 상황에 대응하기 어려움 |

즉, 기존 방식은 영어 지식 자체를 익히는 데는 도움이 될 수 있지만,

실제 회화 상황에서 상대방의 말을 듣고 즉각적으로 반응하는 능력을 기르는 데는 한계가 있습니다.

---

## 3. 한국 영어교육의 구조적 한계: Reading 중심 학습

한국 영어교육은 오랫동안 **수능 중심의 평가 체계**에 큰 영향을 받아 왔습니다.

그 결과 영어 학습은 실제 의사소통 능력보다 **reading, 문법, 어휘 암기**에 치우치는 경향이 있었습니다.

| 수능 중심 영어학습 | 한계 |
| --- | --- |
| Reading 중심 | 지문을 해석하는 능력은 향상되지만 실제 대화 대응력은 부족함 |
| 문법·어휘 암기 중심 | 문장을 분석할 수는 있지만 즉각적으로 말하기 어려움 |
| 정답 선택형 평가 | 자신의 생각을 영어로 직접 구성하고 표현하는 능력을 측정하기 어려움 |
| 듣기·말하기 경험 부족 | 상대방의 말을 듣고 즉각적으로 반응하는 훈련이 부족함 |
| 실제 상황 맥락 부족 | 공항, 호텔, 입국심사 같은 현실적 상황에서 영어를 사용하는 경험이 부족함 |

이러한 구조에서는 학생들이 오랜 기간 영어를 배워도

실제 해외여행, 입국심사, 수하물 분실, 공항 직원 응대 같은 상황에서

자신의 상황을 영어로 설명하거나 문제를 해결하는 데 어려움을 겪게 됩니다.

따라서 본 프로젝트는 기존 reading 중심 학습의 한계를 보완하기 위해

**listening과 speaking 중심의 CLT 기반 학습 경험**을 제공합니다.

---

## 4. CLT란 무엇인가

**CLT(Communicative Language Teaching)**는 영어 학습의 목표를

문법 지식 습득이 아니라 **의사소통 능력 향상**에 두는 교수법입니다.

CLT에서는 학습자가 문법을 먼저 배우고 나중에 적용하는 것이 아니라,

실제 의미 있는 상황 속에서 영어를 사용하면서 언어를 습득합니다.

### 기존 방식

> 문법 설명 → 구문 반복 → 정답 확인 → 오류 수정
> 

### CLT 방식

> 상황 제시 → 영어로 의사소통 → 문제 해결 → 코칭과 피드백
> 

CLT의 핵심은 다음과 같습니다.

| CLT 요소 | 설명 |
| --- | --- |
| Meaning-focused communication | 문법 형식보다 의미 전달을 우선함 |
| Interaction | 학습자가 실제로 듣고 말하며 상호작용함 |
| Fluency | 완벽한 문장보다 대화를 지속하는 능력을 중시함 |
| Context | 실제 상황과 목적이 있는 언어 사용을 강조함 |
| Feedback as coaching | 오류 지적보다 대화를 이어갈 수 있도록 코칭함 |

즉, CLT는 영어를 시험 문제로 다루는 것이 아니라,

실제 상황에서 사람과 소통하기 위한 도구로 다룹니다.

---

## 5. 본 프로젝트의 교수법: CLT 기반 PBL

본 프로젝트는 CLT에 **PBL(Problem-Based Learning)** 구조가 결합된 형태입니다.

PBL은 학습자에게 실제적인 문제 상황을 제시하고,

학습자가 그 문제를 해결하는 과정에서 지식과 능력을 습득하도록 하는 방식입니다.

이 프로젝트에서 사용자는 영어 표현을 단순히 연습하는 것이 아니라,

해외여행 중 발생할 수 있는 돌발 상황을 영어로 해결해야 합니다.

| 요소 | 프로젝트 적용 방식 |
| --- | --- |
| CLT | NPC와 영어로 상호작용하며 의사소통 수행 |
| PBL | 입국심사, 수하물 분실, 공항 직원 응대 등 문제 상황 해결 |
| Listening | NPC의 질문과 반응을 듣고 상황을 이해함 |
| Speaking | 사용자가 직접 영어로 답변하고 문제를 설명함 |
| 자유 발화 | 정해진 선택지가 아니라 사용자가 직접 영어로 말함 |
| 코칭 | 힌트, NPC 반응, 최종 피드백을 통해 학습 지원 |
| 평가 | Task Success, Clarity, Grammar, Politeness, Problem Solving 등으로 분석 |

따라서 이 프로젝트에서 영어는 단순한 학습 대상이 아니라

**문제를 해결하기 위한 도구**로 사용됩니다.

---

## 6. 프로젝트 안에서 나타나는 CLT 요소

## 6-1. 실제 상황 기반 과제

사용자는 다음과 같은 실제 여행 상황을 영어로 해결해야 합니다.

- 입국심사관의 질문에 답변하기
- 입국 목적과 체류 기간 설명하기
- 수하물 분실 상황 설명하기
- 공항 직원에게 도움 요청하기
- 자신의 상황을 논리적으로 설명하기
- 예상 밖 질문에 즉흥적으로 대응하기
- 불완전한 영어로도 대화를 이어가기

이는 단순히 문장을 암기하거나 선택하는 활동이 아니라,

상황 맥락 안에서 의미를 전달하고 문제를 해결하는 활동입니다.

---

## 6-2. Listening 중심 상호작용

기존 reading 중심 학습에서는 학습자가 주어진 지문을 읽고 해석하는 것이 핵심이었습니다.

반면 이 프로젝트에서는 사용자가 NPC의 질문을 듣고,

그 의도를 파악한 뒤 적절하게 반응해야 합니다.

예를 들어 입국심사 장면에서 사용자는 다음과 같은 질문을 듣게 됩니다.

> What is the purpose of your visit?
> 
> 
> How long will you stay?
> 
> Where will you be staying?
> 
> Do you have a return ticket?
> 

이때 중요한 것은 단어를 아는 것만이 아니라,

상대방의 질문 의도를 이해하고 상황에 맞는 답변을 구성하는 능력입니다.

---

## 6-3. Speaking 중심 문제 해결

이 프로젝트의 핵심 활동은 사용자의 **speaking**입니다.

사용자는 정답을 고르는 것이 아니라,

자신의 상황을 직접 영어로 말해야 합니다.

| 기존 학습 | 본 프로젝트 |
| --- | --- |
| 지문 읽기 | NPC 질문 듣기 |
| 정답 선택 | 자유 발화 |
| 문장 해석 | 상황 이해 |
| 문법 분석 | 의미 전달 |
| 시험 대비 | 실제 문제 해결 |

따라서 사용자는 영어를 머릿속으로 분석하는 수준을 넘어,

실제 상황에서 말로 꺼내고, 대화를 지속하며, 문제를 해결하는 경험을 하게 됩니다.

---

## 7. 오류 처리 방식: Minor Error와 Critical Error 구분

CLT에서는 모든 오류를 즉시 고치지 않습니다.

대화 흐름을 방해하지 않는 minor error는 그대로 두고,

의사소통을 방해하거나 시나리오 실패로 이어질 수 있는 global / critical error에만 개입합니다.

| 오류 유형 | 처리 방식 |
| --- | --- |
| Minor Error | 대화 흐름을 유지하고 즉시 개입하지 않음 |
| Global Error | 의미 전달이 어려우면 힌트 제공 |
| Critical Error | 상황 실패 가능성이 있으면 적극 개입 |
| 반복 오류 | 에피소드 종료 후 최종 피드백에서 정리 |

예를 들어 사용자가 관사나 시제에서 작은 실수를 하더라도

의미 전달이 가능하다면 대화는 계속 진행됩니다.

반면 입국 목적을 전혀 설명하지 못하거나,

공항 직원의 질문을 잘못 이해해 문제 해결이 불가능해지는 경우에는

힌트나 NPC 반응을 통해 개입합니다.

---

## 8. NPC의 피드백

NPC는 사용자의 오류를 직접 지적하기보다,

자연스럽게 올바른 표현으로 다시 말하는 **recast** 방식의 피드백을 줄 수 있습니다.

### 예시 1

**User**

> I go travel.
> 

**NPC**

> Oh, you’re traveling for tourism. How long will you stay?
> 

### 예시 2

**User**

> My bag no come.
> 

**NPC**

> I see. Your baggage hasn’t arrived yet. Can you describe your suitcase?
> 

이 방식은 사용자가 대화의 흐름을 유지하면서도

자연스럽게 더 적절한 영어 표현을 접하게 만듭니다.

즉, NPC는 사용자의 말을 끊고 문법을 지적하는 교사가 아니라,

대화를 이어가며 올바른 표현을 간접적으로 제공하는 코치 역할을 합니다.

### 8-1. FonF에서 사용할 수 있는 피드백 유형

recast는 그중 하나일 뿐이고, 실제로는 여러 방식이 있습니다.

| 피드백 방식 | 설명 | 게임 내 적용 |
| --- | --- | --- |
| Recast | 사용자의 말을 자연스럽게 고쳐 다시 말함 | NPC가 대화를 이어가며 올바른 표현을 들려줌 |
| Clarification Request | 의미가 불명확할 때 다시 설명을 요구함 | “Could you explain that again?” |
| Confirmation Check | 사용자의 의도를 확인함 | “Do you mean you are here for tourism?” |
| Elicitation | 사용자가 스스로 고쳐 말하도록 유도함 | “Can you say that in a full sentence?” |
| Metalinguistic Feedback | 문법·표현에 대한 단서를 제공함 | “이 질문에는 방문 목적이 필요합니다.” |
| Explicit Correction | 직접적으로 올바른 표현을 알려줌 | “You should say: I’m here for tourism.” |
| Repetition | 오류가 있는 부분을 반복해 사용자가 인식하게 함 | “You go America…?” |
| Prompt | 더 적절한 표현을 끌어내는 유도 질문 | “Try using ‘I’m here for…’” |
| Input Enhancement | 중요한 표현을 강조해서 노출함 | 핵심 표현을 UI나 자막으로 강조 |
| Delayed Feedback | 대화 중에는 개입하지 않고 종료 후 피드백 | 최종 리포트에서 오류와 개선 표현 제 |

---

## 9. 힌트 시스템

사용자가 의미 전달에 실패하거나 상황 해결에 막혔을 때,

Agent는 필요한 수준의 힌트를 제공합니다.

| 힌트 유형 | 예시 |
| --- | --- |
| 행동 힌트 | “입국 목적을 먼저 말해 보세요.” |
| 단어 힌트 | “tourism, vacation, business 같은 단어를 사용할 수 있습니다.” |
| 문장 힌트 | “I’m here for tourism.” |
| 상황 힌트 | “입국심사관은 체류 목적과 기간을 확인하려고 합니다.” |

핵심은 사용자가 바로 정답을 받는 것이 아니라,

스스로 대화를 이어갈 수 있도록 지원받는다는 점입니다.

이는 CLT에서 말하는 교사의 역할과 유사합니다.

교사는 모든 오류를 즉시 수정하는 사람이 아니라,

학습자가 의사소통을 지속할 수 있도록 돕는 코치입니다.

---

## 10. 최종 피드백 구조

에피소드가 끝난 후에는 사용자의 발화와 문제 해결 과정을 종합해 피드백을 제공합니다.

최종 피드백은 단순 점수 제공이 아니라,

사용자가 어떤 부분에서 의사소통에 성공했고,

어떤 표현을 개선하면 더 자연스러운 영어가 되는지 알려주는 역할을 합니다.

### 평가 항목

| 항목 | 평가 내용 |
| --- | --- |
| Task Success | 상황을 성공적으로 해결했는가 |
| Clarity | 의미가 명확하게 전달되었는가 |
| Grammar | 문법 오류가 의사소통을 방해했는가 |
| Vocabulary | 상황에 맞는 어휘를 사용했는가 |
| Politeness | 공항·입국심사 상황에 맞는 공손함을 유지했는가 |
| Problem Solving | 문제를 논리적으로 해결했는가 |

본 프로젝트는 기존 영어 학습의 한계를 다음과 같이 보완합니다.

| 기존 영어 학습 | 본 프로젝트 |
| --- | --- |
| Reading 중심 | Listening·Speaking 중심 |
| 문법 중심 | 의사소통 중심 |
| 정답 선택 | 자유 발화 |
| 교실 상황 | 실제 여행 상황 |
| 오류 즉시 수정 | 대화 지속 중심 피드백 |
| 단순 회화 연습 | 문제 해결 기반 학습 |
| 결과 점수 중심 | 플레이 후 개선 피드백 |

이 프로젝트는 영어를 읽고 해석하는 능력에서 더 나아가,

상대방의 말을 듣고, 자신의 상황을 설명하고, 문제를 해결하는

실제 의사소통 능력을 기르는 것을 목표로 합니다.

> 기존의 수능 중심 영어학습은 reading, 문법, 어휘 중심으로 이루어져 실제 listening과 speaking 능력을 기르는 데 한계가 있었습니다.
> 
> 반면 본 프로젝트는 사용자가 NPC의 질문을 듣고, 입국심사나 수하물 분실 같은 실제 여행 문제를 영어로 해결하도록 설계했습니다.
> 
> 또한 Agent는 사용자의 발화를 분석해 critical error에만 개입하고, minor error는 대화 흐름을 유지하며, 에피소드 종료 후 최종 피드백을 제공함으로써 CLT적 코칭 구조를 구현합니다.
