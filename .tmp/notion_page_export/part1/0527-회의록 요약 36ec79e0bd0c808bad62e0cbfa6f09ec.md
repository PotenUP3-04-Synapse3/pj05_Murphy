# 0527-회의록 요약

## 1. 회의 목적

0527 회의에서는 최종 프로젝트**「왜 이런 일은 나한테만」**의 프로토타입 범위와 핵심 게임 요소를 구체화하였다.

특히 강사 피드백을 바탕으로 다음 항목을 중점적으로 정리하였다.

- 프로토타입에서 보여줄 핵심 시나리오
- 사용자 영어 수준 분기 방식
- 입국심사 시나리오의 구체적 진행 구조
- 게임적 보상 체계
- 실패 및 엔딩 처리 방식
- Agent의 평가 기준과 역할
- Unreal 구현 요소 및 군중 NPC R&D 방향

---

## 2. 주요 피드백 정리

강사 피드백의 핵심은 **프로토타입이라도 게임의 핵심 구조가 명확히 보여야 한다는 점**이었다.

정리된 주요 피드백은 다음과 같다.

1. 프로토타입 단계에서도 사용자 수준 분기 방식이 구체적으로 필요하다.
2. 시나리오는 내일까지 스토리보드 수준으로 구체화해야 한다.
3. 게임 요소는 단순 장식이 아니라, 사용자가 계속 플레이할 이유가 되어야 한다.
4. 프로젝트의 메인 콘텐츠가 왜 메인인지 명확히 보여야 한다.
5. 사용자 영어 레벨 평가 기준이 필요하다.

이에 따라 프로토타입은 **입국심사 시나리오를 중심으로 구성**하고, 사용자의 답변을 AI Agent가 분석해 진행, 실패, 보상, 피드백으로 연결하는 구조로 정리하였다.

---

## 3. 프로토타입 핵심 방향

프로토타입의 핵심은 다음과 같이 정의한다.

> 사용자가 미국 공항 입국심사 상황에서 영어로 질문에 답하고,
> 
> 
> AI Agent가 사용자의 발화 의도, 영어 수준, 문제 해결 여부를 분석하여
> 
> NPC 반응, 재질문, 힌트, 실패 엔딩, 결과 리포트로 연결하는
> 
> **Unreal 기반 실전 영어 문제 해결 시뮬레이션**.
> 

기존의 단순 회화 게임처럼 정답 문장을 맞히는 방식이 아니라, **불완전한 영어라도 상황을 모면하고 문제를 해결하는 경험**을 중심으로 한다.

## 5. 난이도 및 티어 구조

원래 기획에서는 비행기 스몰토크를 통해 AI가 사용자의 영어 레벨을 자동 진단하는 구조였으나, 프로토타입에서는 구현 범위를 줄이기 위해 **사용자가 직접 티어를 선택하는 방식**으로 진행한다.

### 티어 구성

| 티어 | 성격 | 방향 |
| --- | --- | --- |
| Bronze | 초급자 | 질문이 짧고 명확함 |
| Silver | 중급자 | 기본 질문에 약간의 추가 확인 포함 |
| Gold | 상급자 | 압박 질문, 랜덤 물건 해명, 추가 질문 가능 |

티어에 따라 입국심사대 접근 범위나 NPC 태도, 질문 난이도, 보상 연출이 달라질 수 있다.

예시:

- Bronze: 1번 심사대만 이용 가능
- Silver: 1~2번 심사대 이용 가능
- Gold: 1~3번 심사대 이용 가능

단, Bronze라고 해서 실패 가능성이 없는 것은 아니다.

모든 티어는 동일하게 시간 제한과 실패 분기를 가진다.

## 7. 기본 질문 노드

### Node 1. 여권 제출

- NPC 대사: `Next. Passport, please.`
- 플레이어 목표: 여권을 제출한다.
- 성공 의도: `passport_submit`

예시 답변:

```
Here you go.
Here is my passport.
Passport 여기요.
```

---

### Node 2. 방문 목적 질문

- NPC 대사: `What is the purpose of your visit?`
- 플레이어 목표: 미국에 온 목적을 설명한다.
- 성공 의도:
    - `visit_purpose_travel`
    - `visit_purpose_sightseeing`
    - `visit_purpose_vacation`
    - `visit_purpose_visit_friend`
    - `visit_purpose_business`

예시 답변:

```
I'm here for travel.
Travel이요.
Vacation이에요.
친구 만나러 왔어요. Visit friend.
```

---

### Node 3. 체류 기간 질문

- NPC 대사: `How long will you stay?`
- 플레이어 목표: 체류 기간을 말한다.
- 추출 정보:
    - `stay_duration`
    - `stay_until`

예시 답변:

```
I will stay for five days.
Five days요.
One week이에요.
Until next Monday.
```

---

### Node 4. 숙소 질문

- NPC 대사: `Where are you staying?`
- 플레이어 목표: 숙소 정보를 말한다.
- 추출 정보:
    - `stay_location_type`
    - `stay_location_name`
    - `stay_city`

예시 답변:

```
I'm staying at a hotel in LA.
Hotel이에요.
I stay hotel in LA.
친구 집이요. Friend house.
```

---

### Node 5. 귀국 항공권 질문

- NPC 대사: `Do you have a return ticket?`
- 플레이어 목표: 귀국 항공권이 있음을 말한다.
- 성공 의도:
    - `has_return_ticket`

예시 답변:

```
Yes, I have a return ticket.
Return ticket 있어요.
Next Monday flight입니다.
Korea back ticket 있어요.
```

## 8. 답변 입력 방식

프로토타입에서는 음성 대화의 게임성을 살리기 위해 **눌러서 말하기 방식**을 사용한다.

### 입력 방식

- 상호작용 키: `Space Bar`
- 키를 누르는 동안 녹음
- 키를 떼면 답변 종료
- 답변 제한 시간: 최대 1분

### 시간 제한 처리

- NPC가 질문한 뒤 1분 안에 답변해야 한다.
- 1분이 지나면 답변하지 않은 것으로 처리한다.
- 시간 초과 시 NPC 인내심 또는 감정 상태가 나빠진다.
- 반복 실패 시 코믹 실패 엔딩으로 이어질 수 있다.

## 9. AI Agent 판정 기준

AI Agent는 사용자의 답변을 단순 문법 기준으로만 평가하지 않는다.

핵심은 **상황 해결에 필요한 의미가 전달되었는가**이다.

### 평가 항목

| 평가 항목 | 설명 |
| --- | --- |
| 이해도 | 질문의 의도를 이해했는가 |
| 의미 전달 | 필요한 정보를 전달했는가 |
| 문법성 | 문법 오류가 어느 정도인가 |
| 어휘 적절성 | 상황에 맞는 단어를 사용했는가 |
| 유창성 | 지나치게 끊기지 않고 답했는가 |
| 문제 해결력 | 입국심사를 통과할 만한 답변인가 |
| 태도 | 욕설, 장난, 부적절한 표현이 없는가 |

### 핵심 판정 방향

이 게임은 **정답 맞히기 게임이 아니라 상황 모면하기 게임**이다.

예를 들어 완벽한 문장이 아니더라도,

```
Travel이요.
Five days요.
Hotel in LA.
Return ticket 있어요.
```

처럼 핵심 정보가 전달되면 성공으로 처리할 수 있다.

반대로 문법은 괜찮아도 질문과 무관한 답변, 욕설, 지나친 장난, 불명확한 발화가 반복되면 실패 분기로 이동한다.

## 10-2. 점수 시스템

예시 항목:

- 문법 점수
- 어휘 점수
- 유창성 점수
- 문제 해결 점수
- NPC 인내심 잔여율
- 힌트 사용 여부
- 최종 랭크

---

## 10-3. NPC 인내심 게이지

입국심사관 NPC의 머리 위 또는 UI에 **인내심 게이지**를 표시한다.

### 인내심 감소 조건

- 답변 시간 초과
- 질문과 무관한 답변
- 의미가 불명확한 답변
- 욕설 또는 부적절한 표현
- 과도한 장난성 답변
- 힌트 과다 사용

### 인내심 유지 또는 회복 조건

- 핵심 정보 전달 성공
- 질문 의도에 맞는 답변
- 정중한 표현 사용
- 명확한 재답변 성공

---

## 10-4. 힌트 시스템

단순한 “힌트 버튼”은 학습 앱처럼 보일 수 있으므로, 게임 내에서는 **스마트폰 아이템**으로 처리한다.

### 아이템 예시

> 데이터 로밍 번역기 찬스
> 

### 기능

- 현재 질문에 맞는 추천 단어 제공
- 추천 문장 제공
- 행동 힌트 제공
- 장소 또는 다음 목표 안내

### 패널티

- NPC 인내심 감소
- 최종 점수 감점
- 클리어 타임 감점
- 힌트 사용 기록 표시

이 구조를 통해 사용자는 다음 선택을 하게 된다.

> 안전하게 힌트를 사용해 통과할 것인가,
> 
> 
> 아니면 자신의 영어 실력으로 고득점을 노릴 것인가?
>

## 11. 코믹 실패 엔딩

실패 엔딩은 **코믹한 방향을 유지**한다.

다만 발표에서는 지나치게 과격하게 보이지 않도록, 코믹한 연출로 처리한다.

### 실패 조건

- 1분 동안 답변하지 못함
- 질문과 전혀 무관한 답변
- 욕설 또는 부적절한 표현
- 의심스러운 답변 반복
- 핵심 정보 미전달
- NPC 인내심 0 도달

### 코믹 실패 엔딩 예시

| 엔딩명 | 설명 |
| --- | --- |
| 석 out 엔딩 | 입국심사관이 고개를 젓고 플레이어가 옆방으로 끌려감 |
| 철창 엔딩 | 과장된 코믹 연출로 공항 철창 배경의 실패 화면 표시 |
| 수갑 엔딩 | 지나친 장난 답변 또는 욕설 시 발생하는 코믹 배드엔딩 |
| Secondary Room 엔딩 | 현실적인 이름을 붙인 코믹 추가 심사실 이동 엔딩 |
| 언랭 엔딩 | 점수 산정 불가, 랭크 미부여 |

### 권장 표현

발표 자료에서는 다음처럼 표현하는 것이 적절하다.

> 실패 시 단순 Game Over가 아니라,
> 
> 
> “추가 심사실 이동”, “석 out”, “언랭 처리” 같은 코믹 실패 엔딩을 제공하여
> 
> 사용자의 재도전 동기를 유도한다.
>

## 13. 멀티플레이 요소

멀티플레이는 기획적으로 재미 요소가 크지만, 프로토타입 필수 범위에서는 제외한다.

대신 확장 요소로 유지한다.

### 멀티플레이 방향

- 2인 협동 입국심사
- 팀 랭크
- 서로 부족한 영어를 보완하는 구조
- 실수와 실패를 함께 보는 소셜 재미
- 스트리머 콘텐츠화 가능성

핵심 재미는 다음과 같다.

> 영어를 잘해서 통과하는 재미뿐 아니라,
> 
> 
> 영어를 못하는 사람들이 함께 비벼서 상황을 모면하는 재미.
>

## 14. Unreal 구현 및 R&D 방향

입국심사장의 몰입감을 위해 군중 NPC 구현이 필요하다.

### 군중 NPC 기술 후보

| 방식 | 장점 | 단점 | 적합한 용도 |
| --- | --- | --- | --- |
| DetourCrowd | 빠르게 구현 가능, NavMesh 기반 회피 쉬움 | 많은 인원에서 CPU 부하 증가 | 수십 명 규모 NPC |

### 정리 방향

- 기본 군중 시스템은 Mass AI 검토
- 동선 제어는 ZoneGraph 활용
- 가까운 NPC는 상호작용 가능하게 처리
- 멀리 있는 군중은 Static 또는 Niagara 방식으로 LOD 처리

## 17. 최종 정리

0527 회의 결과, 프로토타입은 **입국심사 시나리오 하나에 집중**하는 방향으로 정리되었다.

사용자는 티어를 선택한 뒤 입국심사장에 진입하고, 입국심사관의 질문에 제한 시간 안에 답변한다.

AI Agent는 사용자의 답변을 분석하여 의도, 슬롯, 영어 수준, 문제 해결 가능성을 평가한다.

평가 결과에 따라 다음 질문, 재질문, 힌트, 통과, 부분 통과, 코믹 실패 엔딩으로 분기된다.

게임성은 다음 요소를 중심으로 구성한다.

- 티어 / 랭크
- 점수 시스템
- NPC 인내심 게이지
- 스마트폰 힌트 아이템
- 여권 및 입국 도장 보상
- 업적 스탬프
- 코믹 실패 엔딩

결론적으로 본 프로토타입은 단순 영어 회화 게임이 아니라,

**사용자의 자유 발화를 기반으로 AI Agent가 상황을 판정하고 게임 시나리오를 동적으로 운영하는 실전 영어 문제 해결 시뮬레이션**으로 정리한다
